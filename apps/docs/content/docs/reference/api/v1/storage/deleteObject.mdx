Deletes a file from S3 storage with per-object permission checks via Keto.

## Authentication
- **Session Auth**: Requires JWT token via Cookie (`omnibase_postgrest_jwt`) or Header (`X-Postgrest-Token`)
- **Service Key Auth**: Requires X-Service-Key + X-User-Id + X-Tenant-Id headers

## Permissions
The requesting user must have `delete` permission on the file. This is satisfied by being the file owner or having a `can_delete` relation in Keto.

## Deletion Process
1. Keto permission check (owner or can_delete)
2. Metadata is deleted from database
3. File is deleted from S3 storage
4. All Keto tuples for the object are cleaned up (best-effort)

If S3 deletion fails, metadata is already removed (eventual consistency).
